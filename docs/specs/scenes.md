# 场景规范

规定一个场景交付什么：场景源码、随机初始化、布局与初态检查。专家程序见[专家规范](experts.md)，轨迹与报告的格式见[专家数据](expert-data.md)，各文件的位置见[资产布局](README.md#资产布局)，命令见[第四章](../tutorials/04-scene.md)。

示例：[000000](../../asset_sources/scenes/000000/)（三抽屉柜与笔）、[000100](../../asset_sources/scenes/000100/)（38 件物体的办公桌）、[000101](../../asset_sources/scenes/000101/)（62 件物体的电子维修工作台，含垃圾桶与桌面杂物）、[000102](../../asset_sources/scenes/000102/)（30 件物体的梳妆台）、[000103](../../asset_sources/scenes/000103/)（按参考照片复刻的电子工作台，布局 0 即照片，垃圾桶在地上）、[000003](../../asset_sources/scenes/000003/README.md)（沿桌边随机摆放的笔放进抽屉，检验通用技能的局部底盘移动与操作）。

## 定位

- 每个场景只有一条高层指令：`tidy up the table`（整理好桌面）。场景不按任务类型命名，也不写成功判据。
- 场景和布局都用普通 Python 模块定义，不另设配置格式；JSON 只用于运行结果。
- 生产分三步：构建场景（采样并检查初态，存下静置后的状态）、生成轨迹（从存下的初态运行专家）、渲染录像（按录制的状态）。

## 场景源码 `scene.py`

- **世界系**：原点在桌面中心正下方的地面，+Z 向上，单位 m、rad。
- `TABLE`：尺寸、高度、板厚、腿尺寸、摩擦。
- `ROBOT`：机器人资产（`robots/<name>`，描述取自其 `robot.py`）、底盘位置与偏航、起始关节（未列出的为 0）。格式上可以有多个机器人，环境目前只支持一个。
- `OBJECTS`：`{名字: {'asset': 'objects/<类别>/<编号>'}}`。尺寸、碰撞几何、关节都从资产读取，场景里不手写。场景原样引用资产的构建产物，不缩放、不覆盖质量、材料或驱动。
- `VIEWS`：录像用的固定视角，渲染时与机器人相机一样按名字选用。
- `IMAGE_VIEW`（可选）：初态图片默认用的视角，取 `VIEWS` 中的名字；不设时用机器人的主相机（`robot.py` 中第一个 RGB 相机）。
- `initialize(layout)`：随机初始化（布局 0），见下节。
- `LAYOUTS`：可选，同一批物体的其他摆法（布局 1、2、…），见[布局](#布局)。

带 articulation root 的资产（抽屉柜）是一个 articulation；没有 articulation root 的多刚体资产（笔帽靠钢珠卡在笔身上）每个刚体各是一个 rigid object。状态和录制中物体的刚体写作 `<物体>:<刚体>`（如 `cabinet:cabinet.drawer3`），刚体名取自资产的 `table1000:name`。

## 随机初始化

`initialize(layout)` 用 `layout.rng` 抽样，写出各物体的位姿（资产坐标系）和关节值。同一 seed 必须得到同一结果，不能用其他随机源。可用的接口（直接写状态、几何查询、`place` / `drop` / `scatter` / `row` 等便捷组合）见 [`layout.py`](../../table_1000/scenes/layout.py)，多个场景共用的摆放组合（立放进笔筒、落进容器、放进抽屉等）见 [`arrange.py`](../../table_1000/scenes/arrange.py)。

- 区域、落点和朝向可以在某个已放物体的坐标系中给出（只取它的偏航）；几何随设定的关节值变化，拉开的抽屉按拉开后的位置参与计算。
- 支撑可以是桌子、物体或桌旁地面 `'floor'`；放在地上的物体（及其中的东西）不算掉下桌。
- `drop`、`scatter` 放下的物体是**松放的**：刚接触支撑，未必放稳。默认要求它们静置后仍留在原来的支撑上；`layout.free_landing = True` 时可以落到任何地方。
- 抽屉柜的约定（`drawer_contents` 依赖它）：刚体 `<类别>.housing` 与 `<类别>.drawer<i>`（1 为最上层），抽屉部件 `front`、`side1`、`side2`、`bottom`，滑动关节 `<类别>.drawer<i>.slide` 向 −Y 拉出。

## 初态检查

框架在 `initialize` 或 `arrange` 之后统一检查（[`initial.py`](../../table_1000/scenes/initial.py)）：

1. **无穿透**：已放物体之间、物体与桌面之间按碰撞几何检查，接触允许，穿透不超过 1 mm。
2. **落稳**（有松放物体时）：静置 3 s。松放物体可以移动，但要留在托着它的、第一个非松放的物体（容器或桌面）的范围内；`free_landing` 时不限。任何物体都不能掉下桌面，机器人不碰任何东西。
3. **静置稳定**：机器人保持不动、再静置 1 s。每件物体的每个刚体相对其支撑（桌子即世界）平移不超过 3 mm、转动不超过 2°，包括非 articulation 的笔帽和钢珠；物体关节变化不超过 3 mm（或 rad），机器人不碰任何东西。

不通过就换下一个子 seed（`default_rng([seed, attempt])`）重新运行，最多 20 次，并记录每次的原因。

通过的初态存进 `initial_states.hdf5`：每个有效 seed 一组，名称为 seed，属性 `seed`、`attempt`，内容为静置后的场景状态（格式同轨迹的 `initial_state`）；文件属性记录场景、机器人、物理后端和提交，布局 n 另记 `layout`。初态固定用 `isaac-cpu` 生成。专家轨迹从这些状态开始，不再重新采样：同一 seed 的摆放由代码确定，但静置后的状态可能有微小差异，所以初态以文件为准。

`initial.json` 汇总本次的 seed、无法初始化的 seed（`invalid`、`without_state`）、平均尝试次数（`mean_attempts`）、静置时每个物体的最大移动（`settle`）和机器人接触（`robot_contacts`），并列出每个 seed 每次尝试的结果与原因。

## 布局

一个布局是同一批物体的一种摆法，由一个摆放函数给出；状态由布局号和 seed 确定。布局 0 是 `initialize`，其他布局在 `LAYOUTS` 中按编号给出：

```python
LAYOUTS = {1: {'quality': 'good', 'description': '<英文说明>', 'arrange': arrange_sorted}, ...}
```

`arrange(layout)` 与 `initialize` 用同一套接口写出位姿和关节，同样从 `layout.rng` 取随机数（落进容器、撒在一片区域的位置），经过同样的检查和重试；不同 seed 得到同一摆法的不同变体。`quality` 标明整理得好还是差，`description` 写明怎么摆，供人评与模型评价对照。布局不需要配套轨迹；编号定下后不再改动，新布局用新编号。

布局 1–10 在各场景中含义一致，五好五差：

| 布局 | 好坏 | 含义 |
| --- | --- | --- |
| 1 | good | 按类收纳 |
| 2 | good | 主要容器左右镜像 |
| 3 | good | 留出一块工作区 |
| 4 | good | 换一种排列（分列、成排、陈列） |
| 5 | good | 能收的都收进容器，放不进的靠边，桌面中间空出 |
| 6 | bad | 堆成一堆 |
| 7 | bad | 放错地方 |
| 8 | bad | 只整理了一半 |
| 9 | bad | 收得马虎，如抽屉没关、东西胡乱塞进容器 |
| 10 | bad | 其余整齐，但有东西碰倒 |

**好的布局**：本子平放进文件筐（放不平才斜放），小物件收进抽屉或小容器，桌面清爽，可以全空。好的布局之间在看得见的地方有明显区别：容器的位置、笔和本子的收法、桌面留空的区域；不能只有抽屉里的内容不同。

**差的布局**：物理上可行，看得出没整理好。

## 场景设计

- 高处或够不到的固定设备（背板、显示器等）可以放在机器人够不到的位置，作为背景。
- 场景缩略图 `thumbnail.jpg` 取布局 0 最小有效 seed 的初态，格式见[README 与缩略图](README.md#readme-与缩略图)。

## 已知限制

- 只在 CPU PhysX、单环境上运行；GPU 与多环境见 [issue #11](https://github.com/xucj98/table-1000/issues/11)。
- `place` 等几何查询的支撑面只有桌面和物体碰撞包围盒的顶面；放进容器、抽屉或叠放用 `drop` / `scatter`。
- 笔的帽与钢珠一直有微米级抖动，不休眠（不影响任务）。
