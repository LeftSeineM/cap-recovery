# 专家规范

场景的专家程序怎么写，以及专家运行时的语义。专家由大模型按本规范编写（code as policy），也可以由人或 agent 交互操作后导出。接口和技能的细节以代码为准：`ctx` 见 [`context.py`](../../table_1000/experts/context.py)，原子技能见 [`skills`](../../table_1000/experts/skills/__init__.py)，语义技能见 [`skills/semantic.py`](../../table_1000/experts/skills/semantic.py)，动作链见 [`skills/chain.py`](../../table_1000/experts/skills/chain.py)，模块说明里有完整的行为描述。技能实现按功能分目录：`skills/hold/`（抓取、换手、薄物体）、`skills/place/`（放置与释放）、`skills/drawer/`（关节测量与扶柜）、`skills/push/`（推、拖与摆正）；场景几何查询在 `world/`，调用与求解记录在 `audit/`，资产抓取评测在 `evals/`。生成的数据见[专家数据](expert-data.md)。示例：[场景 000002](../../asset_sources/scenes/000002/experts/x1pro_rm001/0000.py)。

## 文件与适用范围

专家按机器人分目录、用编号区分：`asset_sources/scenes/<场景>/experts/<机器人>/<NNNN>.py`。编号是 4 位数字，同一场景、同一机器人下从 `0000` 起顺序分配，删除的编号不再复用；编号只作身份，不表达含义。一个专家只服务一个机器人，可以只适用于一个 layout 甚至一个 seed：专家就是一种数据，允许针对一条轨迹完全写死。同一场景、同一机器人可以有多个专家。

文件开头的 docstring 用一句话说明这个专家做什么、和同目录其他专家有什么不同。模块变量：

- `ROBOT`：机器人名，必须与所在目录一致，加载时核对。
- `SCOPE`：`{layout: seed 列表或 None}`，`None` 表示该 layout 的全部 seed。`run_expert.py` 默认运行范围内的全部 layout 与 seed；范围外的请求报错，开发运行加 `--outside-scope` 才允许并在记录中标出，场景的数据不允许越界。
- `SOURCE`（可选）：`hand`（手写）、`harness`（交互导出）或 `agent`。
- `STEPS` 或 `solve(ctx)`，见下文。

同一场景各专家共用的函数可以放在 `experts/common.py`，专家用相对导入引用。

## 分层

| 层 | 回答 | 不管 |
| --- | --- | --- |
| 专家 `experts/<机器人>/<NNNN>.py` | 物体要到哪、按什么顺序；有语义的中间状态（先拉开抽屉再取笔）；每步的判据；风格提示（接近方向、`near`、`keep_out`） | 用哪只手、底盘站在哪、手臂何时收回 |
| 语义技能 `skills.semantic` | 把以名字给出的目标（物体、关节、表面、容器）换成几何约束：放置区域与禁放区、把手与拉动方向、开度；判断结果的谓词 | 怎样满足这些约束 |
| 原子技能与动作链 `skills` | 在约束下选手、握法、交接、躯干和底盘；`chain` 让前一个动作满足后一个动作的需要 | 物体该放到哪 |
| 运动原语 `ctx.solver(arm)`（MPlib） | IK、RRTConnect、直线 screw 运动、执行 | 任务语义 |

专家优先用语义技能和原子技能，不调用 `ready`、`make_room`，也不指定手臂；先挪开哪个物体、挪到哪，仍由专家决定。取放相连时用 `chain`，否则拿起时不会考虑放下的需要。

## 专家与平台的边界

- **专家只写专家脚本**：不改技能和平台代码，不导入私有成员，不替换或修补平台函数。一轮开发内平台冻结；专家写不通的地方先在脚本里绕过并记下，由单独的技能层工作修，下一轮在新平台上重写专家。
- **分工的方向**（技能层改造的目标，现有专家和技能还没有完全做到）：
  - 专家只给语义目标和策略：放进哪个容器、先开哪个抽屉、顺序，以及风格提示；
  - 判据由平台的谓词库唯一定义（#117），专家、技能和任务的最终状态用同一份；
  - 技能执行后自己等到稳定，用同样的谓词验证，失败时返回结构化的原因，由专家决定换什么方案；
  - 技能做决策时的自检只用机器人传感器允许的信息（#116），审计可以用真值。
- 所以专家脚本里的 `ctx.hold` 等待、手算的区域和坐标、手写的判据，都是技能缺口的信号：记入技能缺口清单，不作为长期写法。

## 编写规则

下面的规则与上一节的“优先用语义技能、不指定手臂”适用于覆盖整个 layout 的专家（`SCOPE` 的值为 `None`）。只服务列出的少数 seed 的专家（例如一条轨迹）可以写死站位、手臂、握持部位、释放高度和固定世界坐标，以换取这条轨迹能完成；但目标判据、全场防跌等检查不能放宽，随机仍用 `ctx.rng`，子任务仍要标出。写死的值尽量用相对物体或容器的量表示，便于以后归纳成通用规则。

- 每个目标由物体**当下**的位姿和资产几何算出，不按 seed 或固定世界坐标写特例。
- 需要变化的选择用 `ctx.rng`，不用其他随机源。
- 子任务用 `with ctx.subtask('<英文指令>'):` 标出；数据同时提供高层指令 `tidy up the table` 和子任务指令。
- 直接用运动原语时，手指只在需要的动作里允许接触相应部件，用完撤销（例如只在最后的直线接近时允许碰把手）。
- 可以重试，但要写明候选（物理上等价的抓法与放法、后撤距离）或次数上限，并用 `ctx.note` 记下换用的候选；其余失败用 `ctx.fail(原因)` 结束。
- TCP 约定：+X 为接近方向，+Y 为手指张开方向。
- 资产约定：关节用资产 `model.json` 中的名字（如 `cabinet.drawer1.slide`）；把手是关节子刚体上名为 `handle` 的部件。

## 步骤与检查点

多步任务写成步骤：模块级 `STEPS = [Step(名字, run, check), ...]`，`solve(ctx)` 写成 `run_steps(ctx, STEPS)`。步骤之间手里不拿东西；`check` 检查结束状态是否满足下一步的起始条件，判据用谓词（`require(ctx, 谓词, 原因)`）。

每步通过 `check` 后保存检查点（场景状态与各动作项保持的指令，格式见[检查点](expert-data.md#检查点)）。从第 k − 1 步的检查点运行第 k 步起的步骤时：

- 恢复状态后静置 0.2 s；空闲手臂的姿态和底盘的起始位姿仍取回合开始时的。
- `ctx.rng` 为 `default_rng([seed, attempt, 1, k])`，MPlib 的随机数也随 k 改变；从初态开始时为 `default_rng([seed, attempt, 1])`。
- `--repeats` 重复 K 次时每次换一组随机数，第一次与不重复时相同。

## 有限重试

技能在 `retry` 下执行：失败后恢复回调入口的场景、控制指令、持物和规划状态，换一组随机数再试，包括第一次在内至多 K 次（`--skill-attempts`，默认 3，K = 1 不重试）。

- 它是兜底：确定性的失败要修根因，不靠增加次数。K 不改变候选预算、碰撞条件和物理参数；第一次的随机数与 K 无关；动作链里每个回调分别计次。
- `Unreachable` 也重试；`Unmet` 交给动作链补救；程序错误直接抛出。
- 只覆盖回调内部：`open`、`close` 的内部检查会重试；`place_on`、`place_inside` 结束时的谓词检查和 `Step.check` 在回调外，失败就结束这次运行。
- 主轨迹只保留入口之前的部分和最后一次尝试；sim time 只计这些动作，wall time 与 CPU time 包含被丢弃的尝试。丢弃的分支另存为完整批次（`retry_archives`，见[报告](expert-data.md#报告)）。

## 放置放宽与桌面操作

技能层提供下面几种行为，参数与细节见各模块说明（[`place/low.py`](../../table_1000/experts/skills/place/low.py)、[`drawer/bracing.py`](../../table_1000/experts/skills/drawer/bracing.py)、[`push/squaring.py`](../../table_1000/experts/skills/push/squaring.py)）：

- **低处释放**：严格放置（物体送到最终位姿附近再松手）没有候选或无解时，`place` 改为从容器底面上方松手、让物体落下。落差（物体最低点到实测底面）不超过资产的 `max_drop_m`（缺省 0.15 m，见[建模](modeling.md)），松手前实测复核；容器已有内容物、下落途中可能碰到其他物体、或张开手指会碰到周围时不松手。之后仍按原目标谓词验收。`flat` 放置不走这条路径。
- **扶柜开关抽屉**：`open`/`close` 加 `brace=True` 时，另一只空手压住柜体顶面再拉或推，全程检查柜体位移 ≤ 20 mm、转角 ≤ 5°、其他抽屉被带出 ≤ 20 mm，超限即失败，更小的扰动只记录；重试仍以第一次动作前的柜体位姿为基准。两只手都要空。
- **桌面摆正**：`square_on_table(ctx, obj, xy, yaw)` 只推不抬，每推一次重新测量，直到位置差 ≤ 20 mm、朝向差 ≤ 5°（`yaw=None` 不管朝向）或轮数用完；单次推进很小只记录，剩余误差连续不改善时换接触侧或方向。推的时候容器内一同被带动的物体之间不检查相互碰撞（它们随容器整体移动），外部碰撞照常检查；可传 `check` 在每次推前后检查内容物。
## 判据：以人眼可见的结果为准

步内与步末的判断看动作后的实际结果，不在动作前用预测量否决（#117）：

- **抓取**：闭合后先受控提起 20 mm，两侧手指实际接触、物体随手上升、握持点相对夹爪位移 ≤ 10 mm 才算抓住，再继续抬升；预测的接触面积和计划指距只记录。抓空或滑脱即失败并松手，不空手继续后续动作。
- **收纳**：物体浸入容器、由内底或内壁托住即算在容器内，倾斜（如杯中的笔）只记录。叠在同一容器里已收纳物体上、由它从下方托住的也算（如抽屉里叠在板擦上的胶带）。贴在容器外壁或只从侧面贴着别的物体不算。容器搬运、抽屉推拉时，这样确认在内的物体（包括叠放的）随容器一起规划，它们之间不检查相互碰撞。
- **抽屉关闭**：开度 ≤ 20 mm 即算关上。
- **运动到位**：关节跟踪误差只是诊断；停下后末端离目标 ≤ 20 mm、≤ 5°，或抽屉实测开度已达目标，即算到位。碰撞、丢物或明显偏离仍失败，由调用者换方案。

- **抓空恢复**：抓空后沿接近方向后退，优先换当前躯干和底盘可达的候选；只在这种重试里，躯干小幅升降（≤ 0.15 m）先与手臂联合规划，规划失败再收另一只手臂。首次接触前照常先收臂。

## 失败恢复

每次运行记录调用帧树（步骤 → 子任务 → 技能，见[调用帧](expert-data.md#调用帧)）。从一个技能帧生成的快照，恢复该技能**进入时**的场景、控制指令、持物、规划器挂载与允许接触、规划世界、子任务和随机数，再用原参数只调用这个技能：

- 默认取失败路径最内层的具体技能；步骤 `check` 失败时取该步最后一个具体技能，重跑完再执行 `check`。
- 第 1 次用原随机数，后续 repeats 换随机数；规划时限、物理接触和负载仍可能使结果不同。
- 技能重跑成功只表示这次调用成功，不生成整步完成的检查点。
- 人工遥操的 failure 起点用同样的恢复。没有调用帧的旧批次只能从失败前若干秒的状态重做整步。

## 已知限制

- 只支持滑动关节；转动关节（柜门）需要沿圆弧拖动把手，接近与推动方向随门转动。
- 放置区域由竖直向下的射线求得：被低于下落高度的部件盖住的支撑面（柜内隔板）找不到；支撑刚体的 z 轴须朝上。
- step 内的技能逐个贪心决策，只有显式写出的 `chain` 在相邻取放之间前瞻（联合求解见 [#66](https://github.com/xucj98/table-1000/issues/66)）。
