# 仓库与目录

## 仓库职责

`table-1000` 保存本项目的代码、研究文档、操作手册和资产定义。RoboDojo 等外部仿真框架在各自仓库维护；本项目的使用说明注明命令在哪个仓库执行。外部框架下载的资产与权重遵循其自身约定，不与本项目资产混放。

## 目录

仓库顶层按“由谁产生、是否进 Git”划分：

| 目录 | 内容 | Git |
| --- | --- | --- |
| `table_1000/` | 可复用代码 | 提交 |
| `scripts/` | 命令行入口，只做参数解析和调用 | 提交 |
| `tests/` | 单元测试，子目录与 `table_1000/` 对应（`table_1000/modeling/` → `tests/modeling/`），文件名 `test_*.py` | 提交 |
| `asset_sources/` | 资产源码：建模、物理、场景、专家程序与小缩略图 | 提交 |
| `configs/` | 多个资产或场景共用的配置 | 提交 |
| `docs/` | 文档，分类见[文档写法](writing.md) | 提交 |
| `assets/` | 由源码构建或下载的资产，以及验收看的预览、测试结果和场景初态 | 忽略 |
| `data/` | 生成的数据：专家轨迹及其录像；`data/cases/` 为人工挑选、长期留存的卡点用例 | 忽略 |
| `runs/` | 开发和实验运行，按类型分子目录（`runs/expert/`、`runs/teleop/`、`runs/resolve/`），每次运行一个新目录，不覆盖 | 忽略 |
| `outputs/` | 日志和临时结果，可随时清理 | 忽略 |
| `.local/` | 本机说明与脚本；批量运行时代码的临时检出（`.local/batch-checkouts/`，批次结束后删除，见[批量运行](../tutorials/README.md#批量运行的通用参数)） | 忽略 |

各类资产的文件在 `asset_sources/`、`assets/`、`data/`、`runs/` 中的具体位置见[资产布局](../specs/README.md#资产布局)。忽略目录体积大，多个检出可以用软链接指向同一份。

忽略目录中的内容都可以由代码重新生成：`assets/` 由构建脚本生成或从记录的来源下载，`data/`、`runs/` 由对应的 commit 和命令重跑得到。`runs/` 中的批次记录也是事后整理[实验台账](../experiments/README.md)的原始材料，关心的批次在整理之前不清理；整理好的结论写进台账，不再依赖这些目录。

## 公开内容与本地内容

仓库由多人维护，并计划开源。可复用代码、公共使用说明、设计文档、实验台账和资产源码进入仓库；它们面向任意读者，使用仓库相对路径或明确的路径参数，不依赖特定机器、私有部署或内部任务记录。

凭据、环境目录、内部服务器名与地址、个人部署记录、机器配置和临时调试文件不提交。外部资源引用注明版本、来源和许可。
