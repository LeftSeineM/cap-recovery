# 专家 wall time 优化

这个条目研究在成功率不下降的前提下，怎样降低专家生成中除 PhysX 以外的耗时（规划、IK、碰撞检测、世界维护）。结论是这部分耗时可以降一半左右：场景 000002 的 100 个 seed 新旧代码同时运行，非 PhysX wall time 从 584.7 s 降到 318.9 s（−45.5%），整条 episode 的 CPU time 从 1149.9 s 降到 532.7 s（−53.7%），成功 85/100 → 89/100。在当前 main 上逐项关掉做消融，碰撞粗筛、粗筛缓存、运动链 IK、抓取几何复用四项在三个场景都有明确收益，没有一项是稳定的负优化。早先逐项累计的进程 CPU time 不单调，是因为其中含 BLAS 线程空转，见[单线程 BLAS](../20261027-single-thread-blas.md)。

关联：#43；PR #53、#69（已合入），#84（逐项消融的 commit，已关闭），#85（单线程 BLAS 与本条目），#67（可选的 VAMP 后端，草稿，暂缓合入）。

## 关键问题与结论

- 问题：原版 000002 每条 episode 约 300 s，其中非 PhysX 约 210 s；最大的几项是 RRT（82 s，其中大部分在 MPlib 没有上限的 `simplifyMax`）、IK（56 s）和抓取候选（48 s）。能否在成功率不下降的前提下，把这部分降低 30–50%。
- 结论：
  - 能。#60 之前的代码上，000002 的 100 个 seed 同时对照，非 PhysX wall time −45.5%，CPU time −53.7%，成功 85/100 → 89/100。
  - 这批优化 rebase 到 #60（已经换掉 `simplifyMax`）之后仍有收益：非 PhysX 的线程 CPU time 在 000002 上 −16%，000003 上 −28%，成功 20/20 和 19/20（对照的 main 加了未提交的计时补丁，只作参考）。
  - #69 又把显式碰撞查询的 CPU time 降到原来的约 1/4（000002 上每次 10.9 → 2.8 ms）。
  - 当前 main 上逐项消融（[下文](#逐项消融)）：关掉碰撞粗筛、粗筛缓存增量维护、运动链 IK、抓取几何复用后，对应类别每次调用的 CPU time 分别变为 2.0–4.7 倍、3.4–4.6 倍、1.7–2.0 倍、1.1–2.2 倍，三个场景一致；增量更新规划世界主要减少更新次数。20 seed 下方向不一致的三项在 000002、000003 上补跑 100 seed：裁剪碰撞对在两个场景都有收益，有界捷径化只在 000002 有收益，起点接触逐对失效没有明显的速度差别（它的作用是避免捷径被误判作废）。没有一项是负优化。
  - 早先按加入顺序逐项累计测的进程 CPU time 不单调，原因是进程 CPU 含 BLAS 线程空转，随负载起伏：Isaac 启动时把 `OPENBLAS_NUM_THREADS` 改成 32，启动命令里设的 1 不生效。限制为单线程后，main 在三个场景的进程 CPU time 降低 48%–65%，成功数不变（[单线程 BLAS](../20261027-single-thread-blas.md)）。逐项比较因此改用不含 BLAS 线程的调用线程 CPU time。
  - 换成 VAMP 后端，非 PhysX wall time 还能再降约 21%（88/100）。它需要额外的编译依赖，暂不合入。

## 优化内容

括号内为 PR 和对应的消融组。

**路径规划**

1. 有界路径简化：把 MPlib 没有上限的 `simplifyMax` 换成最多 256 次、限时 2 s 的捷径化，先贪心删多余顶点，再按 TOPP 执行时长挑平滑结果，保证路径不变长（#53，A1）。
2. 近似解不简化：RRT 只给出近似解时直接判失败，不再先花时间简化一遍再丢掉（#53；#60 起入口已不简化近似解，未单独消融）。
3. 换 RRT 后端：用 VAMP（CPU SIMD 的 RRTConnect，机器人用 11427 个球近似）代替 MPlib 搜索，路径仍用精确几何验证；000002 上非 PhysX wall time 再降约 21%（#67，草稿，暂缓合入）。

**碰撞检测**

4. 包围盒粗筛：精确 FCL 检测前先用 AABB 排除不可能碰撞的连杆–物体对，MPlib 原本逐对全部跑 FCL（#53，A3）。
5. 裁剪碰撞对：原生 RRT 规划期间临时关掉固定连杆、手臂够不着的物体这些不可能碰撞的检测对，规划结束后恢复（#53，A4）。
6. 粗筛缓存增量维护：物体移动或切换 padding 时只刷新它自己的包围盒，附着、松开只改受影响的候选对，不再整场景重建（#69，A5）。

**IK**

7. 只在运动链上求 IK：CLIK 只在升降加目标手臂这条链上迭代，不再算全身模型，全身碰撞检查保留（#53，A6）。

**复用与增量更新**

8. 复用抓取几何：手的碰撞凸包只构造一次、按开口更新手指，原来每个抓取候选都重新构造（原版 000002 抓取候选每条约 48 s）（#53，A7）。
9. 增量更新规划世界：只更新位姿或 padding 变了的物体，不再每次重建规划世界，并保留碰撞许可（#53，A8）。

**修正优化带来的副作用**（不直接提速，但保住了提速）

10. 起点接触按碰撞对处理：捷径化时每对接触只允许离开、离开后失效，避免捷径被误判成碰撞而作废（#53，A9）。
11. 推动按剩余行程重试：推到一半失败时换下一个候选，从物体的实测位置只推剩余距离，不从头重复（#53）。

**测量方法**（不提速，但让提速可信）

12. 按项计时：`--profile` 下每一项同时记录 wall time 和调用线程的 CPU time，物理步单独记进程 CPU time，机器负载很重时也能比较（#53）。
13. 新旧同时跑：每次对比都让新旧代码在同一时段、同样参数下运行，只看相对降幅，并记录负载。

**评估过但没采用**

14. cuRobo（GPU 规划）：调研时只在关闭碰撞的情况下测了 IK，接入需要补齐碰撞与附着，还要和 Isaac 共用 GPU；CPU 上的 VAMP 更合适，没有接入。
15. 硬件指令计数：代码已接好，但容器没有权限读性能计数器（`perf_event_open` 返回 EACCES），目前不启用。

- A3 关掉粗筛时，依附于粗筛的 #69 缓存也一起停用，所以 A3 与 A5 不能相加。碰撞查询每次调用也变为 1.69 / 1.29 / 2.14 倍。
- A5 的收益只在显式碰撞查询上，它在 000002、000003 中占比很小，端到端看不出差别；000103 物体多，碰撞查询每条从 9.7 s 增到 43.8 s。
- A8 每次调用差别不大，收益在调用次数：000003 关掉后世界更新次数从 54.9 万增到 88.9 万，每条 CPU time 为 A0 的 1.60 倍。
- A1 退回的旧贪心删点把碰撞检查记到路径验证里，所以合计 RRT、路径验证和 TOPP 一起比较。100 seed 下 000002 为 1.31 倍，但增量有 73% 集中在 3 个 seed；000003 为 1.04 倍，20 seed 时的 1.30 倍没有保持。
- A4 关掉后每次 RRT 调用 CPU 为 1.22 / 1.17 倍，其中原生求解 1.42 / 1.22 倍；000003 在 20 seed 时的 0.90 倍没有重现。RRT 在整条 episode 中占比不大，端到端只有 1.07 / 1.02 倍。
- A9 为 1.01 / 1.09 倍，000003 在 20 seed 时的 0.61 倍没有重现。
- RRT 受时限约束，跑满时限的失败调用会拉高每次调用的均值：000002 中这类调用占 2%–5%，000003 中占 24%–31%。所以 RRT 类别 20 seed 的结果波动很大，以 100 seed 为准。
- 20 seed 各组分散在可见逻辑 CPU 不同的主机上，平均负载/核数在 0.5–1.4 之间；超线程争用会抬高线程 CPU time，例如 000002 的 A3、A7、A9 负载约 1.4，A0 约 0.6。相差 2 倍以上的结论不受影响，1.1–1.3 倍的差别只作参考。100 seed 补测各组负载为 0.55–0.68。

## 复现

每条结果的 commit 和命令都在 csv 中：[ablation.csv](ablation.csv)（逐项消融）、[final100.csv](final100.csv)（开头的 100 seed 对照）。在干净的检出上执行 `git checkout <commit> && bash -c '<命令>'`。

- 000002 用场景自带的初态。000003、000103 的初态（`--input`）来自更早的批次，不能由这些 commit 重建，这两个场景的结果是历史观察。
- 000103 的消融每组实际分两批运行（seed 0:10 与 10:20），合并后与 csv 中的 `--seeds 0:20` 等价。
- 开头的 100 seed 对照都在 #74 之前，用的是未开 CCD 的旧笔资产；原版一侧加了未提交的计时补丁（只改计时汇总），这组对照是历史观察，不作为复现依据。非 PhysX wall time 为 `expert_wall_s - wall_profile.physics_step.wall_s`。

环境：双路 AMD EPYC 7542（每台 64 核 128 线程，容器可见 56–128 个逻辑 CPU），RTX 4090，与其他实验共享机器。20 seed 消融 27 批每批 1 个并发进程；100 seed 补测 8 批每批 4 个，总并发 32。
