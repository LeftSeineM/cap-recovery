# 资产抓取测试与专家耗时

场景 000103 的 29 个一般尺寸资产，第一次抓取就抓稳的比例从 60.9% 变为 96.6%（前后评价流程不同：新测试的持物动作比旧测试的来回晃动温和得多，难度更低）。专家生成数据的 CPU time 比 main 增加 7%–17%，成功率不变。资产测试本身每次的 CPU time 增加到 3.4 倍，几乎全来自水瓶和辅助夹具两个资产，其余 27 个只增加 45%；这两个资产在 #90 优化。另一个局限是持物动作的实测强度只有专家持物运动 P99 的 20%–45%，在 #89 处理。

关联：#42，PR #54。逐资产、逐场景的数字以及 commit 和命令见 [assets.csv](assets.csv)、[experts.csv](experts.csv) 和 [queries.csv](queries.csv)。

## 为什么

**为什么资产测试慢得多，专家几乎不受影响。** 新增的计算都在挑选握法上：每个候选都要对真实碰撞面做接触查询，并按重力力矩和抗扭能力打分。资产测试一次试次的物理仿真只有约 15 s，其余时间几乎全花在挑握法上，所以增加得多。专家 episode 的大头是物理仿真、RRT 规划和放置等子任务，挑握法只占一小部分。水瓶的碰撞面片多，一次试次要比较约 800 个候选。辅助夹具有 18 个可抓部件，首次失败后还会换一个部件再试一次以收集握法偏好，这一次也计入耗时。

**为什么换评价指标。** 旧测试是：抬起后手腕在 ±0.4 rad 之间来回摆动，每段 0.5 s，端点瞬间反向；看物体顶点位移是否不超过 5 mm；失败后换握法重试，任意一次通过就算通过。它有三个问题：
- 摆动远超专家实际的持物运动，会把专家够用的握法判成失败；
- 顶点位移随物体尺寸放大，大物体只要轻微转动就超限；
- 重试掩盖了"第一次抓不稳"，而专家第一次失败就要回滚重来。

新测试只看第一次抓取。抬起后拿着物体做三段平滑的持物动作：横移 50 mm、上移 50 mm、手腕转动约 1 rad。判据是握持点相对 TCP 的位移不超过 5 mm、转角不超过 5°。持物动作的强度上限是专家持物运动的 P99：线加速度 1.13 m/s²、角速度 1.23 rad/s、角加速度 3.01 rad/s²，取自 000002 的 264 条成功轨迹中的 530 个持物区间。够不着的记为"未评估"，实测速度或加速度超出强度上限的记为"动作无效"（这次持物动作比规定的更剧烈，掉了也不能说明抓不稳），都单列，不算夹持失败。

## 局限

- **持物动作的强度不足（#89）。** 持物动作在关节速度和加速度上限内取最短时间，实测峰值只有专家实际持物运动 P99 的一部分：横移平均 38%、上移 23%、转动 42%。转动只用最后一个腕关节（0.8 rad/s、1.5 rad/s²），上移用升降关节（0.2 m/s²），都远低于 P99。
- **两个资产太慢（#90）。** 见上文。

## 附录：迭代过程

**改动：**

- r1：换成新测试；闭合时检查真实指腹接触；候选按重力力矩排序。
- r2：持物动作预检四个等价方向；圆柱件要求指腹插到中心截面。
- r3：各部位按重力力矩与抗扭能力统一排序；指腹支撑按真实接触层计算。
- r4：改评价流程，不改抓取策略：原地做不了持物动作时，先挪到可达的参考起点再测，此后不再出现"未评估"。
- r5：复用角度预检时已经算过的接触。
- r6：真实碰撞面的射线求交用 Numba 编译。
- r7：接触小矩阵的计算限制为单线程 BLAS，消除 r6 带来的线程空转。
- r8：先检查平行约束面。
- r9：合入 main（含 #69）并整理模块；对照的 main 从 `3150aee` 换成 `f5c6be7`。
- r10：同一凸块、同一方向复用查询计划。
- r11：先检查完全闭合，用外包粗筛排除不可能相交的查询。
- r12：用完整转角作为枚举下界。
- r13：按完整手腕转角排序，只用于有后续手持要求的抓取。
- r14：持物动作限速，并检查实测速度和加速度是否超出强度上限（审查修复）。
- r15：在关节上限内取最短时间，并对持物做整段碰撞预检（复审修复）。

- **分母：** 资产首次抓稳的分母扣除了无法判断是否抓稳的试次，共两类。一类是"未评估"：抓起来了，但原地做不了持物动作，出现在 r2、r3（2 次、7 次），r4 改评价流程后消失。另一类是"动作无效"：持物动作时实测速度或加速度超出强度上限，这项检查从 r14 才开始做，r14 有 2 次（键盘持物转动时撞到 lift_link），r15 加持物碰撞预检后消失。
