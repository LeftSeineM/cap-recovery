# 笔 000002 开启 CCD

运动碰撞时，笔 000002 笔帽里的钢珠会穿过抽屉的薄底板、把抽屉夹住，导致 000000 偶发失败；PR #74 在 CPU PhysX 上为笔开启 CCD 修复了这个问题。代价是 CPU time 增加大概 3%，而且 GPU PhysX 不支持 CCD。

关联：#43（000000 偶发失败的排查），PR #74（修复）。

## 2026-10-26 钢珠穿板的修复与代价

### 问题

笔 000002 的笔帽里有 3 颗 0.8 mm 的钢珠，通过径向弹簧关节连在帽壳上，盖帽时卡住笔杆上的凸棱，起锁扣作用。笔掉进抽屉、撞到 3.5 mm 厚的底板时，帽壳在一个 4 ms 物理步内压进底板约 1.5 mm（最深 6.1 mm），下侧的钢珠被挤到底板下方（球心在底板顶面以下 4.3 mm）。帽壳在板上、钢珠在板下，关节把两者连着，笔就夹住了底板：钢珠与底板的接触力约 23.5 N，关节被拉开 4.5 mm，而设计行程只有 0.8 mm。之后关抽屉或手离开把手时，抽屉被顶开 5.8–7.6 mm，超过 5 mm 的关闭阈值。

PR #74 在 CPU PhysX 上为笔的 5 个刚体（笔杆、帽壳、3 颗钢珠）开启 CCD（连续碰撞检测），几何、质量、关节、材料和 4 ms 步长都不变。这个条目回答三件事：CCD 能否阻止钢珠穿板，物理计算多花多少时间，用到这支笔的三个场景（000000、000002、000003）成功率是否回退。

### 结论

- 防穿板：薄板跌落测试的 12 种落高与姿态组合中，不开 CCD 时 10 种的钢珠穿到板顶以下（最深 −4.30 mm），开 CCD 后 0 种（球心最低 +0.80 mm）。GPU 上开不开 CCD 结果逐值相同，CCD 不生效。
- 场景效果：同一份代码上 000000 跑 20 个 seed，不开 CCD 19/20，失败的 seed 18 正是抽屉被笔夹住（开口 5.803 mm）；开 CCD 20/20。
- 代价：CPU time 增加约 2–3.5%。000000 的 20 个 seed 同时对照，物理部分每个控制步的 CPU time 从 55.13 ms 增加到 57.08 ms（+3.5%），wall time +2.9%；薄板测试 12 轮交替运行，每个物理步 CPU time +1.9%。
- 当前 main 上的回归：000000 19/20 → 20/20，000003 持平 19/20，000002 20/20 → 19/20。000002 新增的失败是抓笔接触面积很小、搬运途中笔从夹爪滑落，与钢珠无关，快照重放也没有稳定复现；PR #74 按这一分析合入，共享的笔资产已于 2026-10-26 重建。这组批次的耗时差异在 ±5% 的噪声内，不用来衡量代价。

### 结果

**薄板跌落**：3.5 mm 薄板，落高 6/9/12 cm × 滚转 0/20/40/60°，共 12 种组合，旧笔资产，只切换 CCD。判据是钢珠球心始终不低于板顶面 −0.1 mm。

| 后端 / CCD | 钢珠穿到板顶以下的组合 | 钢珠球心最低 (mm) | 帽壳最大压入 (mm) | 钢珠与板的最大接触力 (N) |
| --- | --- | --- | --- | --- |
| CPU / 关 | 10/12 | −4.30 | 6.14 | 26.7 |
| CPU / 开 | 0/12 | +0.80 | 0.21 | 0.38 |
| GPU / 关 | 10/12 | −4.30 | 4.25 | 4.2 |
| GPU / 开 | 10/12 | −4.30 | 4.25 | 4.2 |

**耗时**：两组同时运行，耗时为物理部分（`physics_step`，含动作转换、物理推进和记录，不含规划）的总时间除以总步数，即均值。

| 测试 | 指标 | 关 CCD | 开 CCD | 变化 | 负载 / 核数 |
| --- | --- | --- | --- | --- | --- |
| 000000，seed 0:20，同时运行 | 成功 | 19/20 | 20/20 | | p50 0.25 / 0.25 |
| | CPU time（ms / 控制步） | 55.13 | 57.08 | +3.5% | |
| | wall time（ms / 控制步） | 45.24 | 46.54 | +2.9% | |
| 薄板跌落，12 轮交替 | CPU time（ms / 物理步） | 97.50 | 99.36 | +1.9% | 均值 0.21 / 0.28 |
| | wall time（ms / 物理步） | 29.97 | 31.20 | +4.1% | |

薄板测试中开 CCD 的几轮负载更高，wall time 的 +4.1% 有一部分来自负载；CPU time 受负载影响小，以它为准。

**当前 main 上的回归**：两组运行同一份代码 `015b2da`（#74 分支，已包含 main 上的 #69），只有笔资产不同。每个场景 seed 0:20，120 条 episode 全部有结果，没有进程错误；没有调整物理参数，也没有用重跑结果替换失败。合入要求是每个场景的成功数不低于旧资产。

| 场景     | 旧资产   | CCD   | 失败 seed         | CPU time 变化 | 负载 / 核数 p50 旧 / CCD |
| ------ | ----- | ----- | --------------- | ----------- | ------------------- |
| 000000 | 19/20 | 20/20 | 旧组 18（钢珠夹板）     | −5.58%      | 0.595 / 0.478       |
| 000002 | 20/20 | 19/20 | CCD 组 18（搬运中滑落） | +0.99%      | 0.565 / 0.558       |
| 000003 | 19/20 | 19/20 | 两组均为 13，机制不同    | −3.44%      | 0.561 / 0.563       |

CPU time 变化只比较两组都成功的 19 个 seed。每个场景只有 19 对，配对 bootstrap 的 95% 区间宽约 ±5%，分辨不出 3% 的差别；000000 的旧组负载明显更高，所以出现了下降。耗时以上面的同时对照为准。

### 失败分析

- **000000 旧组 seed 18**：抽屉最终开口 5.803 mm，超过 5 mm 阈值，是上面描述的钢珠夹板；CCD 组同一 seed 成功。
- **000002 CCD 组 seed 18**：第二次从桌面抓笔时，左手指尖与笔的接触面积为 9.75 mm²，旧组同一次抓取为 103.25 mm²。step 1922 提起结束时笔相对 TCP 只漂移 0.056 mm，到 step 1945 已漂移 58.68 mm，夹爪直到 step 2004 才张开，笔从闭合的夹爪中滑落到桌面。两组在这之前的接触过程和抓取候选已经不同，不是同一次抓取。从这条失败的放置入口取快照，新旧资产各重放 3 次：旧资产 2/3、CCD 3/3，旧资产的一次重放出现了同类滑落。所以没有证据表明 CCD 会让抓取变弱；重放结果不替换主批次的 20/20→19/20。
- **000003 seed 13**：旧组失败在放置不可达（114 个候选都没有规划出路线）。CCD 组搬运时推动了柜子，柜子 yaw 从 21.965° 变为 59.119°，平移约 125 mm，放置却仍然用推动前的抽屉区域，笔落在了抽屉外的桌面上，不是穿过底板，也不是搬运中滑落。这是专家的问题：环境被推动后，放置区域没有重新计算。

### 复现

薄板跌落和 000000 的同时对照在 #74 之前的代码 `3150aee` 上，用本地的临时启动脚本切换 CCD，批次带 `+dirty`，没有可复现的命令，属于历史观察。在 #74 的 commit 上，薄板测试可以直接验证开启 CCD 的笔（下面第三条命令）。

当前 main 上的回归：`CCD_ASSETS` 是只构建开启 CCD 的笔的单独资产目录，其中其他资产用软链接指向共享的 `assets/objects`。`SCENE` 依次取 000002、000003、000000；`VARIANT` 取 old 或 ccd，对应的 `ASSETS` 分别是共享资产目录与 `CCD_ASSETS`，每个场景的两组同时启动。000003 追加 `--input <000003 初态目录>`，初态的 SHA256 见备注。

```bash
git checkout 015b2da91ba759301d921a7e0e01c0ed937d714a
blender -b --python-exit-code 1 -P scripts/assets/build_assets.py -- --output ${CCD_ASSETS}/objects --assets pen/000002
uv run python scripts/assets/build_physics.py --output ${CCD_ASSETS}/objects --assets pen/000002 --gpu 0
uv run python tests/physics/isaac_pen_thin_shelf.py --asset ${CCD_ASSETS}/objects/pen/000002/object.usdz --output outputs/pen-ccd-thin-repeat --gpu 0
uv run python scripts/scenes/run_expert.py ${SCENE} --physics isaac-cpu --dev --profile --seeds 0:20 --jobs 4 --gpus 0 1 2 3 --name pen-ccd-current-${VARIANT} --assets ${ASSETS}
# 000002 CCD 组 seed 18 的放置入口快照与重放；BATCH 为 CCD 组 000002 的批次目录，SNAPSHOT 为快照命令的输出目录
uv run python scripts/experts/failure_snapshots.py ${BATCH} --seeds 18 --frame 36 --name pen-ccd-seed18-place
uv run python scripts/scenes/run_expert.py 000002 --physics isaac-cpu --dev --profile --steps 5 --from ${SNAPSHOT} --seeds 18 --repeats 3 --jobs 1 --gpus 0 --name pen-ccd-seed18-replay-${VARIANT} --assets ${ASSETS}
```

共享资产已按 #74 重建，现在在 main 上运行，默认用的就是开启 CCD 的笔。

### 环境

AMD EPYC 7542，128 逻辑核，RTX 4090；Isaac Sim 5.1.0、Isaac Lab 2.3.2.post1，CPU PhysX，物理步长 0.004 s，每个控制步 10 个物理步。所有批次与其他任务共享机器，由显存队列调度；每组对照的两边同时运行。

### 备注

- GPU 上 CCD 不生效：Isaac Lab 的 GPU 管线关闭了状态回读，PhysX 启动时提示 `Physics suppress readback and physicsScene enabled CCD does not work together, CCD will be disabled`。生成数据用的是 CPU 后端。
- 000000 同时对照的开 CCD 组同时打开了场景级的 CCD 开关，所以它衡量的是"场景开 CCD 加笔的 5 个刚体开 CCD"的总代价。
- 当前 main 回归的两组资产只差 CCD：组合后的 USD 有效属性共 3429 项，只有笔的 5 个刚体的 `enableCCD` 从 false 变为 true。实验前后，共享资产中的旧笔和三份初态的校验都没有变化。
- 000000、000002 用共享初态，000003 用 #60 的同一批 20 个初态。三份初态 HDF5 的 SHA256：
  - 000000：`4f938628e060e902150b804c2b92eaaa0b93d0b6c25ab7508912b822ed2f656e`
  - 000002：`b4d986964fc30aab0c6b8744f22c184977ff448a9bcfb93c5debe307925466be`
  - 000003：`40989a9f53c18eea26f19cd5ea61637a22b3c2d259e750b4db0c0b66dff5b36e`
