# Skill 层：专家、skill、primitive 与谓词库

## 决定

专家程序之下分为 skill、primitive、共用计算和执行四层，各层共用一个谓词库：

```
专家       STEPS：每个 step 调用一次 skill（目标参数 + hints + 前瞻范围）
  │
skill      Put / Open / Close / PushTo：按状态路由选下一段、组合局部选项、按前瞻范围规划、失败出口、记录搜索过程
  │
primitive  Move / Grasp / Carry / PlaceAt / Release / Push / Slide / Articulate / JointPush / Press / Drive / Torso
  │          每个对应一个数学问题：自己生成候选、规划、执行前检查、执行、等稳定、验收效果谓词
  │
共用计算   IK、碰撞世界、路径规划与重接、时间参数化、夹爪几何、状态预测、支撑与接触查询
执行       控制步、跟踪、物理仿真

谓词库     各层共用的唯一判据定义
```

### 分层与边界

| 层 | 职责 | 输入 → 输出 | 只能调用 | 不能做 |
|---|---|---|---|---|
| 专家 | 任务分解与策略：step 的顺序、每个 step 的目标、提示与前瞻范围 | `STEPS` | skill、谓词库 | 写站位、坐标、等待、时间预算、判据；调用 primitive 或共用计算（临时越界除外） |
| skill | 按实测状态路由、组合局部选项、按前瞻范围规划、失败出口，验收目标谓词，记录搜索过程 | 目标参数 + hints + 前瞻范围 → `{ok, predicate, measured, reason, tried}` | primitive 的 `plan` / `check` / `reconnect` / `execute`、谓词库 | 构造几何或数学问题，调用共用计算，发控制步，判定失败类别 |
| primitive | 把意图写成一个数学问题，生成和排序自己的候选，求解、执行前检查、执行、等稳定、验收效果谓词，声明可动对象与需维持的关系 | 意图 + 禁忌集 + 偏好 → `plan`：解与预测状态，或无解与原因；`execute`：`ok` 或 `mismatch` | 共用计算、执行、世界模型、谓词库 | 调用别的 primitive；重试；在规划阶段改变物理状态；自行决定挪底盘、收手等补救 |
| 共用计算 | 数值计算 | 数值问题（对象、附件、允许接触以参数传入）→ 结果或失败原因 | 机器人模型、规划世界 | 涉及任务语义；按 primitive 名分发；执行 |
| 执行 | 控制步、跟踪、仿真 | 轨迹 → 实测状态 | — | 做决策 |
| 谓词库 | 唯一的判据定义 | 状态 → 真假与测量值 | 世界状态 | 在各层重复定义 |

依赖只向下，同层之间不互相调用。通用采样算法可以放在共用计算；"这个物体生成哪些抓取或放置候选、怎样排序"只在对应 primitive 中定义一份。

新能力按以下顺序判断归属：
1. 需要新的决策变量或约束，就是新的 primitive；
2. 是已有 primitive 的新组合或新的局部选项，归 skill；
3. 出现新的目标谓词，就在谓词库中加谓词，并加一个新的 skill；
4. 只涉及某个场景、某个任务的顺序或目标，写在专家脚本里。

### Primitive

一个 primitive 对应一个能单独求解、执行后能单独判定的问题，以它所解的问题命名。求解方式相同并不意味着是同一个问题：Grasp 和 Move 都要算 IK 和路径，但 Grasp 有两指对夹的约束，所以分成两个 primitive。

每个 primitive 提供四个操作：

- `plan(状态, 意图, 禁忌集, 偏好)` 只求解，不改变物理状态。按偏好顺序给出解，每个解附带预测的执行后状态；把已用过或被排除的解加进禁忌集再调用，就得到下一个解。无解时说明原因（哪个约束排除了全部候选：IK 不可达、与某物体碰撞、区域里没有空位、开口不够等），并标明搜索是否完整：因截断、预算用完或随机路径未找到而停止的不算"已证明无解"。PlaceAt 可以只返回放置边界（静止位姿、释放位姿、接近位姿），供 skill 先选放置再规划到达它的 Carry；边界不能执行，必须连成完整的解。
- `check(解, 当前状态)` 在执行前判断这个解是否仍可用：规划时依赖的机器人构型、实际握持、附件、允许接触和碰撞世界完全没变就直接可用；只有机器人起点或握持在容差内变化、环境与附件没变时需要重接；其他情况不可用。
- `reconnect(解, 当前状态)` 不换决策，只按实测重接（例如 PlaceAt 按实测握持重算释放位姿和下降段、Carry 重接起点），返回完整的新解，预测状态、绑定、可动与维持声明和来源都随之更新。被替换的绑定（如释放位姿）的尚未执行的使用者（如后续 Release）随之失效，改用新绑定重接或重新规划，不能直接执行旧解。
- `execute(解)` 执行到终止条件，等物体和机器人稳定，然后检查效果谓词。全部成立返回 `ok`；否则返回 `mismatch`，并附上不成立的谓词、实测值和预测值。前置条件不成立时不执行。

其他约定：

- primitive 自己不重试，执行中不重新规划。参数只在 primitive 内定义一份，hints 作为目标函数中的偏好传入。
- 每个解声明本次允许运动的物体与关节，以及必须维持的关系（正在按压、抽屉随动时其中的物体仍在抽屉内、持物时其上的物体仍在其中）。执行层统一检查"其余全部不变、维持的关系全部成立"，基准是执行前的实测状态；检查时发现实测成员变化（如抽屉里多了物体）就按实测重建这两组。
- 持续存在的状态（例如正在按压的手）会进入后续问题的世界模型。

| Primitive | 数学问题（决策变量 / 约束） | 前置条件 | 判据：执行后成立的效果谓词 |
|---|---|---|---|
| Move | 到给定位姿或关节配置的路径 / 无碰撞 | — | TcpAt(解) |
| Grasp | 抓取位姿、接近方向、开口，以及到达路径 / 两指能对夹、开口足够、无碰撞 | HandEmpty | Grasped(obj) |
| Carry | 带着物体先竖直抬起，再到 PlaceAt 给出的接近位姿 / 带载无碰撞 | Grasped 或 Held | Held(obj) ∧ ObjAt(obj, 预测位姿) |
| PlaceAt | 区域内的静止位姿与释放位姿，以及从接近位姿到释放位姿的带载下降路径 / 落差不超上限、在区域内、无碰撞、满足要求的姿态 | Held(obj) | Held(obj) ∧ ObjAt(obj, 释放前的预测位姿) |
| Release | 结束这只手的接触，包括抓空或滑脱后的松爪：张开宽度或抬离距离，以及撤离路径 / 不碰周围 | — | HandEmpty ∧ ¬Pressing；接在 PlaceAt 之后时另加 Resting(obj) 和 PlaceAt 区域上的关系（Inside 或 OnTop，以及要求的姿态）；松开把手时另加 JointAt 不变；撤按压时另加 Unchanged(柜体)；恢复过程中松开物体时只检查 Unchanged |
| Push | 平面推动：接触点、方向、距离 / 推动方向能让物体稳定跟随 | — | ObjAt(obj, 预测位姿, 宽容差) |
| Slide | 压住顶面拖动：接触点、压入深度、路径、终点 / 摩擦足以带动，物体不被压翻 | — | ObjAt(obj, 终点)，例如伸出桌边 |
| Articulate | 握持关节运动：手抓着把手，末端轨迹随关节运动（平动走直线，转动走圆弧），构成闭链 / 整段 IK 可解、内力小 | Grasped(把手) | JointAt(joint, 目标) ∧ Grasped(把手) |
| JointPush | 非握持推关节：在可动部件表面选接触点，沿关节方向单侧推，转动件的接触点沿表面滑动 / 无碰撞、在限位内 | — | JointAt(joint, 目标) |
| Press | 固定表面上的按压位置与到达路径，到达后保持按住 / 接触面合适 | HandEmpty | Pressing(hand, surface) |
| Drive | 底盘路线 / 无碰撞，持物时碰撞检查包含手里的物体 | TorsoAt(≥ 安全高度)，没有手在按压 | BaseAt(站位)；持物时另加 Held(obj) |
| Torso | 升降 / 过程中无碰撞；持物升降时带载无碰撞 | — | TorsoAt(高度)；持物时另加 Held(obj) ∧ ObjAt(obj, 预测位姿) |
| 全部 | | | 另加：除声明可动者外全部 Unchanged，声明需维持的关系全部成立 |

只在执行后判断，不在动作前用预测量否决。有些结果当场验证不了，由下一个 primitive 的效果来判：抓得牢不牢看 Carry 的 Held 和 ObjAt，松手后有没有放好看 Release 的 Resting 和区域关系。

### 谓词库

primitive 的前置条件和效果、skill 的目标、任务终态都用同一套谓词，参数取自规划的解或专家给的目标参数。

| 层次 | 谓词 |
|---|---|
| 机器人 | TcpAt(pose)、BaseAt(pose)、TorsoAt(h)、GripperAt(gap)、HandEmpty(arm) |
| 接触与持握 | Grasped(obj)、Held(obj)、Pressing(hand, surface) |
| 物体状态 | Resting(obj)、ObjAt(obj, pose, tol)、Unchanged(物体集合) |
| 关系与关节 | Inside(obj, container[, part])、OnTop(obj, surface)、Clear(region)、Upright(obj)、Flat(obj)、JointAt(joint, q)、Open、Closed、Aligned(objs) |

谓词只在实测状态上判定。规划时各段之间的衔接读上一段解声明的预期结果（例如"右手对物体建立了抓取""左手按住柜体"），不在预测状态上判 Held、Pressing，也不为了让预测值通过而放宽谓词。

容差与口径初值：

| 谓词 | 容差与口径 |
|---|---|
| TcpAt、BaseAt | 20 mm / 5° |
| TorsoAt | 5 mm |
| GripperAt（张开） | 3 mm |
| Grasped | 该手已建立对目标的抓取，且没有确认抓空。确认抓空有两种，各自充分：确认空合到底（4 µm 是闭止残差的口径，不能只凭裸开口值或缺一侧接触报告确认），或目标按几何位置不在两指之间。确认抓空不能被数值抖动、宽容差内的静态接近或之前的随动记录推翻。接触报告缺失（例如一侧指垫没有接触报告）、与预期接触宽度的偏差、合爪过程中物体的位移都只记录，交给提起后的实际随动来判 |
| Held | 抓取完成后，对当前物体与当前抓取有有效的随动证据：手在主动运动（与仿真静止时的数值噪声区分开），物体的运动与手一致；并且物体上的夹点相对手滑动 ≤20 mm。绕夹点的转角只记录。随动证据不足既不算确认抓空，也不算 Held：已 Grasped 时可以去抬起，真实抬起后仍不成立才算 `mismatch`。预测的持握、过期的基准、合爪前被碰动的物体都不能建立 Held |
| 带载 ObjAt | Carry、PlaceAt、持物 Torso 执行完后物体位姿与预测相差 ≤20 mm / 10°。容差内的滑动只记录，后续规划以实测握持为准 |
| 放置后的区域关系 | 静止后在目标区域内，放进容器时即满足收纳谓词。与规划落点的偏差和倾斜只记录 |
| OnTop | 由支撑关系判定：物体与支撑面接触距离 ≤3 mm 且受其支撑，不另设高度条件 |
| Upright、Flat | 仅在专家要求姿态时检查，倾斜 ≤15° |
| HandEmpty（松手后） | 两侧指垫无接触，物体不随手移动 |
| Open、Closed | 开：≥ 目标 − 20 mm；关：≤ 20 mm |
| ObjAt（摆正目标） | 20 mm / 5°。单次 Push 的效果容差更宽 |
| Unchanged 的对象写法 | 整个物体（`cabinet`）、物体的一个刚体（`cabinet:drawer1`）、物体的一个关节（`(cabinet, drawer1.slide)`）。开关抽屉时只放行目标抽屉与它的关节，柜体和其他抽屉照常检查 |
| Unchanged：柜体与其他抽屉 | 柜体 20 mm / 5°，其他抽屉 ≤20 mm |
| Unchanged：其他物体 | 位移 ≤20 mm、转角 ≤10°。超出后，倒下（物体参考竖直轴相对初始倾斜 ≥45°，绕竖直轴的转动不算）或落到桌下（物体最高点低于桌面）才算失败，其余只记录 |
| 抽屉中的物体 | 抽屉开关时随抽屉运动，按 Inside(抽屉) 检查，不按 Unchanged |
| Resting | 只看物体的根刚体，用相邻观测的位姿差分速度：线速度 <5 mm/s、角速度 <5°/s，连续 0.2 s；最多等 2 s |

### Skill

一个 skill 对应一种目标谓词，负责在各种物体和关节类型上让这个谓词成立。物体和关节类型的差异由 skill 内部选择不同的局部选项来处理，例如平动关节用直线 Articulate，转动关节用圆弧 Articulate 或 JointPush；远距离搬运就在 Put 里加一段持物走位，走位前需要的升躯干由 skill 显式调度 Torso。

skill 成功结束时目标谓词成立，手是空的，也没有手在按压。失败时先回到这次调用的入口状态，再把失败交给专家，所以失败出口与入口状态相同，不会带着持物或按压进入下一个 step。

| Skill | 目标谓词 |
|---|---|
| Put(obj, into / on, …) | Inside 或 OnTop，物体静止，手空 |
| Open(joint, amount) | Open |
| Close(joint) | Closed |
| PushTo(obj, pose) | ObjAt，20 mm / 5° |

Pick、Place、Handover、Navigate 是 Put 内部的段或局部选项，不对专家开放。

#### 状态路由

skill 不预先写好整条 primitive 序列。每次开始、每段执行完、每次失败后，它按实测状态查路由表，决定下一段要做什么；每一段由几个局部选项组成，选项按状态组合，每个选项声明适用条件和出口。因此 skill 可以从任意中间状态继续，不需要知道上一次停在哪一步。路由只做判断，不调用 primitive 求解。

Put，按顺序匹配，第一条命中即用：

| # | 实测状态 | 下一段 | 段内局部选项 |
|---|---|---|---|
| 1 | 目标成立 | 结束，不做动作 | — |
| 2 | 除手空、未按压、静止外，目标谓词都已成立（包括要求的姿态和 `keep_clear`），手仍接触物体或有其他接触 | 撤手 | Release，可选收手 |
| 3 | 目标关系成立、手已离开，只差静止 | 等待 | 保持当前控制目标继续仿真并观测，不发新的运动；超时算 `mismatch` |
| 4 | 某只手已对物体建立抓取，已有选定的放置，且手在它的接近位姿 | 放下 | PlaceAt → Release，可选收手 |
| 5 | 某只手已对物体建立抓取 | 送达 | 未 Held 时先抬起（Carry 抬起或持物升躯干）；再在原地、持物走位、换手及其组合中选 → Carry → PlaceAt → Release |
| 6 | 有手确认抓空，或有多余接触 | 清理 | Release、收手 |
| 7 | 其余（空手） | 获取 | 直接抓、先收另一只手、先 Slide、调躯干、走位及其组合 → Grasp；出口是抓取建立 |

第 4、5 行要求那只手的抓取来自已执行的 Grasp。获取段只到抓住为止，抬起属于送达段：贪心求解不必先单独抬一次，联合求解可以把抬起和后续 Carry 合成一次运动；已经抬起后 Carry 不再重复抬起。

Open / Close：

| # | 实测状态 | 下一段 | 段内局部选项 |
|---|---|---|---|
| 1 | 目标成立且双手空、未按压 | 结束 | — |
| 2 | 关节已达目标，仍握着把手、顶着可动部件或在按压 | 撤手 | 按安全顺序 Release，收手 |
| 3 | 已握住把手或顶住可动部件，扶柜时实测已按住柜体 | 驱动 | Articulate 或 JointPush，从实测开度到目标，可按剩余行程分几段接力 |
| 4 | 其余 | 接触 | 先做准备（直接、收手（两种顺序）、调躯干、走位），再 Press 扶柜（见下），再 Grasp(把手) 或接触；按压期间不走位 |

参与的手（抓取手、扶柜手、交接的两只手）来自状态和选项的绑定，不写死左右手。

开关柜体上的关节时默认扶柜：走到位、做完准备后，先用另一只手按住柜体再驱动，驱动完先松开把手或撤离可动部件、最后撤扶柜的手。柜体固定在支撑上、找不到可按的位置，或另一只手被别的事占着（已经在扶这个柜体不算）时才不扶。专家可以用 `brace=False` 关掉扶柜；它写在 hints 里，但和其他 hints 不同，是硬开关而不是偏好。不扶时仍按 Unchanged(柜体) 验收。

PushTo 的路由允许多次回到同一段（每次 Push 后重新测量），联合求解只规划到下一次测量为止，不把 Push 的预测当作最终可达的证明。

#### 前瞻范围

专家在 step 上用 `lookahead` 选择执行前要规划多远，默认 `auto`：

| `lookahead` | 行为 |
|---|---|
| `none` | 不前瞻：只规划当前这一段，执行，再按实测状态路由下一段。当前段可以正常求解 IK 和路径，但挑候选时只能用当前状态、资产几何、hints、固定的排序规则，不对后面的段求解，也不用缓存里后面各段的可行性结果来筛选当前候选 |
| `full` | 整体前瞻：从当前状态把剩余各段一起规划：后一段无解时，它的无解原因回传给前一段，前一段把导致这个原因的决策加进禁忌集再给出下一个解；全部有解后逐个执行 |
| `auto` | ① 按 `none` 做一次；② 失败后不回滚，从实测状态按 `full` 求解；③ 仍失败就回到入口，按 `full` 求解，物理失败过的决策加入禁忌；④ 仍失败，失败出口，交给专家。①在任何动作之前就无解时直接进入③（不需要回滚） |

执行中的检查：每个 primitive 执行前，skill 对它调用 `check`：可用就执行，需要重接就 `reconnect` 后执行，不可用或重接失败就按当前前瞻范围处理（`auto` 进入下一步）。不再在每段执行后把剩余计划全部重新求解。

禁忌分两种：规划时被否决的决策（与状态有关）和物理失败过的决策。回到入口后只带上后一种。抓取换位置的标准：新的接触中心离所有物理失败时的实测接触中心（同一刚体的局部坐标）≥20 mm，只换方向不算；失败时没有测到接触中心，就禁用那个决策本身，可以试别的决策，但不算已经换开 20 mm；只有适用的候选全部枚举完、确实没有替代时才报"没有别的位置"，证据缺失和预算用完分别报告。规划失败不产生物理失败的接触中心。

局部选项的默认顺序：抓取先在同一抓取族里换候选，再换抓取族（整体 → 部件（把手、侧壁、边缘，按资产标注）→ 薄物体路线），再换站位，再换手；放置先在同一区域内换落点，再换姿态（目标参数允许时），再低处释放，再换站位，再换手。多个选项轮流取下一个候选，避免第一个选项耗尽预算；轮不到的记为"预算用完，未尝试"。

#### 缓存

- 物体局部坐标下未过滤、未排序的原始候选几何（抓取族、放置姿态族）按资产、部件和族参数区分，在一次运行内复用；运行内机器人与手的模型、资产与固定几何不变，变了就失效。用场景障碍、手的朝向过滤或排序过的候选不属于这一层。
- 求解结果在一次 skill 调用内复用（包括回到入口之后），但键必须精确：primitive、意图、hints、两种禁忌、候选数上限，以及完整的规划世界（所有物体位姿、关节、夹爪开度、附件与实际握持、允许接触、按压、碰撞余量）和机器人构型。不做量化近似。
- 没有搜索完的无解（截断、预算用完、随机路径未找到）不缓存为无解，只保存续搜的位置；续搜位置绑定查询输入和已评估范围，不带旧的截止时间。输入、禁忌或预算变了就按当前查询继续搜，不把上一次截断当作完整无解。
- 缓存命中要记录，复用的解关联到当前状态和来源，不当作新求解。

#### 预算

- 每次 skill 调用共享一个 10 min 的 wall time 上限，三步求解和中途回到入口都在其中；到时不再开始新的求解或执行。失败出口的那次回到入口不计入，到时也必须完成；回不到入口是程序错误，不作为普通失败返回。程序异常同样先回到入口再抛出。
- 真实求解（未命中缓存的 `plan`、放置边界、`reconnect`）最多 256 次，缓存命中不计；单条联合规划最长 24 个 primitive；候选上限：抓取原始 128 个、完整 16 个，放置 64 / 16，站位 4 个，交接 8 种。

#### 记录与失败类别

skill 只记录搜索过程的事实：每次求解的输入、结果与原因、是否完整；每次检查、重接和执行；每个实测谓词的测量值；路由到的段、选用的局部选项、所在的求解步骤（①②③）；每次回到入口的用途（为继续尝试，或失败出口）及触发它的事件；缓存命中；各段的规划、检查、执行耗时。skill 不判定也不记录失败类别。

a1、a2、a3、b 在读记录时由分类函数推出（见[专家数据](../specs/expert-data.md#step-内失败)），可视化和统计都用它。按定义：由 `mismatch` 触发、在原地恢复成功的是 a2；只因规划无解在原地另找到路线的是搜索成本；为继续尝试而回到入口时，规划失败触发、丢弃了已执行动作的是 a1，检查失败触发的是 a3，类别只看触发它的事件，不看最后是否成功；失败出口的那次回到入口不另计 a1、a3；失败以失败结果或异常交给专家的是 b。

### 专家与 step

一个 step 只调用一次 skill。step 的检查就是这个 skill 的目标谓词，子任务标注由 skill 按段自动生成。专家能给的信息有三类：

| 类别 | 例子 | 性质 |
|---|---|---|
| 目标参数 | 容器和部件、要求的姿态（`orientation='upright'` 或 `'flat'`）、相对关系、开度、必须空出的区域（`keep_clear`） | 硬约束，写进目标谓词并在验收时检查；不写姿态就不检查姿态 |
| `hints` | 抓取部位、接近方向、手臂、`near`、放置朝向、可以放弃的避让区（`avoid`） | 软约束，作为目标函数中的偏好；没满足不算失败，但记录是否满足 |
| `lookahead` | `auto`（默认）、`full`、`none` | 执行前规划多远，不能用来传预算或容差 |

```python
STEPS = [
    Step(put('notebook_a5', into=('cabinet', 'drawer2'), orientation='flat'),
         hints=dict(grasp_part='spine', approach='top', arm='right')),
    Step(put('pen_black', into='cup', orientation='upright'), lookahead='none'),
    Step(close(('cabinet', 'drawer1'))),
]
```

`keep_clear` 和 `avoid` 共用同一份区域定义和 Clear 谓词：前者写进目标谓词并验收，后者只作偏好。Put 的 `keep_clear` 只约束被放的物体不进入该区域（Clear(region, objects=(obj,))），不要求区域内原有的其他物体移走；要求整个区域清空需要另外的目标。现有的 `keep_out` 在放置候选过滤和验收中都是硬约束，迁移为 `keep_clear`。

hints 一律相对物体或资产来写，用部位名、功能点或物体坐标系里的方向，不写世界坐标。资产知识（可抓部位、把手、功能点、`max_drop_m`）写在资产里；预算和容差属于平台配置。

现有技能不够用时可以临时越界，但只能写在专家脚本里，并在每处标记 `# 越界(<应归的层>): <原因>`。一轮开发期间平台冻结。每轮结束后按这些标记汇总成 skill 缺口清单，下一轮补进平台，再删除脚本中对应的越界代码。

资产抓取评测不经过专家：它用平台内部的 Grasp → Carry → Release 配方，走同一套 skill 调度、记录和预算；运输是否抓稳另按 TransportStable（5 mm / 5°）评定，这个容差只用于评测。

## 依据

- 000100 第二遍的两份专家脚本共约 5000 行，大部分在替 skill 层干活：
  - 手写放置区域 53 个函数；
  - 运行时替换技能方法 11 处、私有导入 6 处；
  - `ctx.hold` 39 处、自设时间预算 24 处、手写判据 159 处；
  - 捕获异常后自行补救 18 处。
- 20 条 a3 中只有 11 条是真实物理失败。其余是三类问题：判得过早（实提 2 cm）、动作前用预测量否决（松手前 4 mm 门槛）、只看接触报告。另有失败类型被专家手写错。
- 回滚重试会选回同一个抓取候选，技能内部的原地恢复（a2）为 0。抓起来以后才发现放不下的规划回滚（a1）两条线共 28 次。
- 第一版实现（11-03）用约 20 条写死的完整 primitive 序列表达 Put，每条都从入口整链求解：
  - 场景 CPU 中 73–85% 花在规划上，000002 三个 seed 抓取规划 217 次、742 s，000003 放置规划 77 次、778 s；同一 step 内 71–87% 的抓取规划输入与之前某次完全相同，失败的 IK 和路径没有缓存，回溯时重复验证；
  - 只能从入口求解，执行到一半失败后无法原地继续；
  - 修复轮里成功的 step 中 154/159 在 5 min CPU 内完成，全部在 10.5 min 内；失败的 step 有 2 个用满了 20 min。
- 第一版的 Held 用"手的微小运动 + 夹点误差在容差内"作随动证据，把一次合爪到底、物体在指外的真实抓空判成了抓住（000000 seed 0，手的位移约 5 µm）。
- 每层的职责参照了同类工作：
  - BEHAVIOR 的 action primitives 与 BDDL 目标谓词一一对应，并区分前置条件错误和后置条件错误；
  - RoboCasa365 按基础技能组织原子任务；
  - RoboTwin 2.0 用资产标注的接触点和功能点表达抓取偏好；
  - MoveIt Task Constructor 把规划拆成 stage，由 Alternatives、Fallbacks 容器组织备选与回退；
  - PDDL 算子用前置条件和效果描述动作。

## 适用边界

- 谓词和 primitive 直接读仿真状态。按传感器能力限制决策可用的信息（#116）是单独的工作。
- 回到入口只用于现在的开发环境。以后作为 robot harness 由 agent 调用、并记录全轨迹时，需要禁止回滚，失败处理和失败出口届时另定。
- 不做跨 skill 的前瞻：step 的顺序由专家安排，顺序排错记 b。
- 不做多个身体部件的并行运动（#44）。
- 现阶段的 skill 只覆盖目标谓词 Inside、OnTop、Open、Closed 和摆正；关节只承诺平动（抽屉），转动关节只留接口。开启机构的差异（抽屉直拉、转动门直接拉开、要先转把手解锁再拉的门）由资产描述：关节类型，以及哪个关节锁住哪个关节、转到多少解锁。Open 按这些描述选局部选项，专家只给目标和 hints；某种机构的选项要等平台支持它、并且资产描述与仿真里的物理关系一致后才生效，不预先做通用框架。先解锁再拉需要新的谓词（锁止状态）和新的约束（拉门时保持把手转开），届时按新能力的归属规则加入。按钮与旋钮（Toggle、Turn）、擦拭倾倒等状态改变类操作，需要新的谓词、skill 或 primitive。
- 推动的结果难以精确预测，所以 Push 的效果容差放宽，是否到达目标由 PushTo 判断。
- 容差、预算和候选上限都是初值，按回归结果调整。

## 未采用的方案

| 方案 | 原因 |
|---|---|
| 按求解形式归并 primitive（Reach / MoveStraight / Gripper / Drive / Torso） | 不同的约束被混在一起，判据无从定义 |
| Pick、Place 对专家开放 | 拿着物体再去放的前后衔接要专家自己保证，这正是规划回滚的主要来源 |
| 专家手写 chain 串联取放 | 不写就没有前瞻，前瞻是否存在取决于专家的写法 |
| primitive 内部重试 | 换哪种方案需要 skill 的上下文，在 primitive 内重试会重复选同一个候选 |
| 原子判据与目标谓词分开定义 | 同一个结果会有两套判据；效果谓词本身就能表达原子判据 |
| step 带预写的备选（失败后平台改试下一个） | 失败被运行时回退掩盖，step 的结果取决于走了哪条路；专家应看记录后直接修改这个 step |
| 一个 step 内包含多个 skill 并由专家写 `check` | 搜索树、检查点和 b 的计数单位对不上，判据也会散落在专家脚本里 |
| skill 用写死的完整 primitive 序列清单，总是整链联合求解 | 新情况就加一条，组合数增长；序列之间重复求解；只能从入口求解，做不了原地恢复（见依据） |
| 按"第一个未完成的段"判断进度 | 松手后"已拿到"又变成不成立，会把已放好的物体再抓一次；需要显式的状态路由 |
| 执行后把剩余计划全部重新求解 | 调用数随链长平方增长；改为每个 primitive 执行前自己检查、必要时重接 |
| skill 在运行时记录失败类别 | 分类定义一改就要重跑；记录事实、读时分类可以随时改定义 |
