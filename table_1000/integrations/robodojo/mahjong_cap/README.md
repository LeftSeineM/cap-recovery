# RoboDojo make_kong CAP v020

这份包保留已验证 v020 的 13 个 Python 模块及 3 个小型动作先验的原始字节。它在外部 RoboDojo worker 中完成匹配牌亮牌、左手取补牌、双臂交接、右手独立携带和最右放置。它使用仿真真值与既有动作先验。

| 能力 | 适用条件与参数 | 停止条件 |
| --- | --- | --- |
| 入场稳定 | 已朝上的匹配牌保持朝上；其余匹配牌在最多24个原生等待动作内达到直立或朝上，且连续3次线速度<0.02m/s、角速度<0.20rad/s | 非目标牌倾斜≥7°；超出等待界限；已完成牌偏离朝上≥30° |
| 选臂 | 按未完成匹配牌的平均世界X选择手臂，全部已完成时回退到全部匹配牌 | 当前臂 IK、关节或跟踪失败即停止；本版无自动换臂 |
| 接触推倒 | 以实测牌姿变换26个参考路点；已形成部分推倒时最多10个2mm同向追加路点 | 旁牌守卫失败；撤离后目标Z轴偏离朝上≥30° |
| 抓取与交接 | 补牌初姿与先验位置差≤5mm、姿态差≤3°；同作业固定持物参考，实际抬升与右手独立携带验证 | 抓空、持物参考漂移、原生预算不足或状态守卫失败 |
| 最右放置 | 用逐例重绑的实际碰撞边界计算右缘和间隙，执行支持释放 | 原生终态未同时满足end与success；XY误差≥15mm或朝向/间隙不合格 |

`env` 是已初始化的单环境 RoboDojo worker，`emit_action` 是调用方唯一原生动作入口。每次提交须推进一步并记录动作、实际状态和原生标志。完整调用前置条件见[接入说明](../../../../docs/tutorials/robodojo-mahjong-cap.md)。这不是 Table-1000 `ctx` skill 的直接替代品。

`enabled_collision_bounds.json` 是已验证案例的几何示例。运行每个新源之前，调用方须为实际全部类别重绑资产SHA和边界；禁止沿用不匹配的表。三份NPZ分别是26路点推牌模板、抓取和交接的短动作先验，总计约12KB；原始episode、视频和训练轨迹未包含。
